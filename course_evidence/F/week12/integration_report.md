## 4. 观察到的问题

**① 写得多、合得少**

昨天六个人都交了东西，但一个 PR 都没开，全部堆在分支上。
今天就出现了「四个分支落后 main 9~33 个 commit」的局面。
**代码不合进 main 就等于不存在**，而且拖越久冲突越大。

**② 真模型数据一度不可信**

D 第一版真模型报告显示 5/5、每个 1.1~2.0 秒，耗时和假模型几乎一致。
排查发现 `default_client()` 在没有 `LLM_API_KEY` 时会**静默退化**成 FakeLLM，
跑出来照样 100%，报告上完全看不出来。

已修（PR #14）：实验输出第一行强制自报客户端身份，没 key 时 stderr 发出警告。
D 重跑后输出 `OpenAICompatClient (model=deepseek-chat)`，耗时升到 1.5~2.9 秒，
这次是真数据。

**教训**：任何"降级"都不能静默。静默降级会让假数据穿上真数据的外衣，
而且没人会发现。

**③ 当前 5/5 的修复率说服力有限**

五个用例都是很浅的错（缺冒号、函数名拼错、少个加号）。真模型全 1 轮通过，
说明不了模型强弱，只能说明**管路是通的**。

要证明"闭环迭代有价值"，必须有不通过的用例——第一轮失败、第二轮才过的过程，
才是这个项目真正的卖点。已把这个需求派给 D。
