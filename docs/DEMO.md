**6 分钟。目标只有一个：让人相信这不是演出来的。**

核心叙事：

```text
这是一段真坏的代码
  → 系统真的修好了（第 1 轮）
  → 也有它修不好的（第 3 轮仍失败）

```

## 二、演示流程（6 分钟）

### ① 开场（30 秒）

> 「我们的项目是一个网页版的代码修复代理。
>
> 现在的 AI 改代码工具大多是一次性给建议——它说改好了，你也不知道真的假的。
> 我们做的是把它闭成环：模型生成的修复，**真的跑一遍测试**，
> 不通过就把报错回灌给它，再来一轮。」

---

## 四、现场翻车预案

| 情况 | 怎么办 |
|---|---|
| 浏览器打不开 | 重新双击 `启动演示.bat`；还不行就直接演示终端实验 |
| 服务窗口被关了 | 双击 `启动演示.bat`，它会重启（会提示端口已占用则直接开浏览器） |
| 上传后一直 pending | 看服务窗口有没有报错；有就说「后台任务出问题了」，切终端演示实验 |
| 对比区空白 | 换传 `examples/syntax_error/greet.py`，这个更快 |
| 网络断了 | **不影响**，演示全程本地跑，不需要网络 |
| 完全跑不起来 | 播备份录屏，然后口头讲架构 |

**唯一不会翻车的保险：备份录屏。提前录，提前试播一次。**

## 六、可能被问到的问题

**Q：这个 5/7 是不是说明系统不行？**
> 不是，是说明用例有区分度。简单用例内置模型就能过，难例需要真模型 + 迭代。

**Q：用户传的代码会不会搞坏服务器？**
> 副本隔离、超时、输出上限、只收 `.py`。但**没做容器级隔离**，这是已知局限。

**Q：六个人怎么不改乱？**
> 目录即所有权，CI 强制查路径和提交人。改别人的目录 PR 直接红。

**Q：最有技术含量的部分？**
> 沙箱的资源控制（超时 + 输出截断 + 目录隔离），和闭环的失败回灌。

**Q：为什么用假模型？**
> 为了 CI 不依赖网络和钱，也为了测试可复现。真模型能力另外测，两者分开。
